## 📖 项目简介

本项目是基于第一次结对作业（需求分析与原型设计）成果落地实现的核心 Web 程序。系统针对校园生活场景中“寻物与招领信息极度分散、班级群容易刷屏遗忘、跨圈子检索困难、物品归还后无法及时闭环”的现实痛点，构建了一套轻量级、结构化、即开即用的校园失物互助集散平台。

### 核心业务闭环
- **信息浏览**：清晰区分【寻物启事】与【失物招领】双主视图，展示物品缩略图、状态标签、遗失/拾获地点及时间。
- **智能搜索与多维过滤**：支持按物品名称、地点关键字模糊搜索，支持关键词**黄色背景高亮**显示，支持物品分类、地点大区、进行中/已结贴状态复合筛选。
- **结构化发布**：支持切换发布类型，具备严格的前端白盒输入校验（防空白、防超长、手机号/QQ号合规检测），支持本地图片上传预览与隐私保护。
- **物品详情与安全交接**：沉浸式卡片展示实物大图、详细特征与防诈安全警示，提供**一键复制发布人联系方式**至剪贴板功能。
- **发布管理（我的发布）**：可以编辑自己发布的信息、删除记录，或标记为已找到/已归还。变更会保存到当前浏览器，并同步刷新本地页面；不会同步到其他人的浏览器。

## 🚀 测试人员快速上手与使用说明

本系统完全依照作业“**在下载所有文件后，用谷歌浏览器运行 html 文件就能展现预期结果**”的标准构建，无需安装 Node.js、Python 或任何数据库，下载整个项目文件夹后即可查看。示例物品图保存在 `assets/` 目录中，离线打开也能正常显示。

### 1. 运行主应用程序
1. 将本项目整个目录（或从 GitHub 仓库 Clone/下载 ZIP）解压至本地任意路径；
2. **使用 Google Chrome 谷歌浏览器**（推荐）直接双击打开项目根目录下的 **`index.html`**；
3. 页面立即载入内置的福州大学精选校园失物招领数据集（包含校园卡、AirPods、折叠伞、钥匙、高数课本等真实数据）；
4. 页面所有数据会自动通过 `localStorage` 缓存在当前浏览器中，支持刷新后数据不丢失！

### 2. 核心功能操作走查路径
- **查看与检索**：
  - 点击顶部的热门标签（如 `学生卡`、`AirPods`、`钥匙`）体验秒级即时筛选；
  - 在搜索框输入任意字符（如 `一区食堂`、`黑色`），卡片上的匹配文字会自动以黄色 `<mark>` 高亮呈现；
  - 切换顶栏的【寻物启事】与【失物招领】Tab，查看不同类别的瀑布流卡片。
- **查看详情与一键复制**：
  - 点击任意卡片进入详情模态弹窗，点击右下角【**一键复制**】，系统会自动将联系方式写入剪贴板并弹出 Toast 提示。
- **发布新信息**：
  - 点击右上角绿色【**+ 发布信息**】按钮；
  - 切换选择“我丢失了”或“我拾获了”；
  - 填写物品名称、分类、发生地点、时间与联系方式，可上传本地图片；
  - 点击“确认发布”，系统经过前端白盒校验后成功保存，新卡片**立即置顶展示在首位**！
- **更新状态（闭环结贴）**：
  - 点击右上角【**我的发布**】打开管理弹窗；
  - 点击任意进行中物品旁的【**标记已解决**】，该信息状态即刻流转为“已结贴”，列表徽章变更为已解决，终止无效联系。
- **编辑自己的信息**：
  - 在【**我的发布**】中点击【**编辑**】，表单会自动回显原有内容；
  - 修改标题、分类、地点、日期、描述或联系方式后点击【**保存修改**】；
  - 系统会沿用发布时的输入校验，并同步更新首页、详情和我的发布列表。
  - 原图片会回显，可以替换或移除；点击“取消”会返回“我的发布”，不会保存修改。
  - 已解决的信息仍可修改内容，但 ID、发布时间、发布者和已解决状态保持不变。
  - 保存失败时会保留输入内容并提示失败，便于继续修改。
  - 发布、删除、标记已解决和重置也会检查是否保存成功。保存失败时提示错误，保留原有数据；发布失败时不关闭表单。
  - 删除与标记已解决仅限自己的记录。浏览器中已保存的空列表在刷新后仍为空，不会自动恢复示例数据；需要示例时可手动重置。

这里的“自己的记录”由本地示例中的 `isMine` 标记区分，没有登录或服务器鉴权，不能作为真实多用户权限系统使用。

### 3. 助教评测辅助工具
点击顶栏右上角【**评测与测试**】下拉菜单：
- **重置为初始精选校园数据**：点击后一键恢复初始干净数据，方便助教反复评测；
- **导出当前数据 (JSON备份)**：一键将浏览器中的最新数据导出为 JSON 文件；
- **导入 JSON 备份**：先校验全部记录，确认后才替换当前浏览器中的数据；
- **运行自动化单元测试**：一键跳转至单元测试运行器，检查搜索、表单、图片、存储和导入等功能；

## 🧪 自动化单元测试说明

本项目包含 **56 个核心测试用例**，位于 `test/unit_tests.js`。浏览器运行器使用自定义断言，没有引入 Mocha 或 Chai。每个用例使用独立的内存存储，执行实际的数据读取与保存方法，不读写用户的 LocalStorage 发布记录。

另有 **20 项页面逻辑测试**，位于 `test/app_tests.js`，在 Node.js 中使用隔离的模拟 DOM、FileReader 和 Image 执行实际页面方法，检查上传回调顺序、损坏图片、取消、重复提交、导入确认、弹窗关闭和保存失败重试。这些检查不替代浏览器中的图片解码与页面显示验证。

直接在浏览器中打开 **`test/test_runner.html`** 文件。页面将自动执行 56 项核心测试，并呈现可视化报告。若已安装 Node.js，也可以在项目目录运行 `node test/run_tests.js`，同时执行核心测试与 20 项页面逻辑测试，无需安装依赖，任何一项失败时返回非零退出码。

## 搜索与日期规则

搜索将关键词作为普通文字匹配，支持 `&`、尖括号、引号和 `C++` 等内容。匹配忽略大小写、去除关键词首尾空格，并保留原文大小写。高亮前先在原文定位，输出时分别转义文字，避免破坏 HTML 实体或插入可执行标签。

发布和编辑都要求日期为 `YYYY-MM-DD`，且必须是实际存在、不会晚于本地今天的日期。默认日期和日期选择器上限使用本地日历，避免 UTC 与本地时差造成日期偏移。表单和数据层共享校验规则。

历次优化、问题原因和验证记录保存在 [开发记录](docs/开发记录.md)，用于后续整理课程博客。

## 图片上传与提交

实物照片支持 PNG、JPG、JPEG、WEBP，单张必须大于 0 字节且不超过 2MB。选择文件后会检查 MIME 类型与扩展名，再读取并确认可以解码；成功后才替换预览，失败时提示并保留原图。连续选择另一张图片、移除图片或关闭表单后，先前的读取结果不会再覆盖当前状态。

图片读取时不能提交表单，保存期间也会禁用提交按钮。成功后关闭表单，忽略后续重复提交事件；保存失败保留输入并恢复按钮，可重试。新增记录遇到相同毫秒的 ID 时会递增避让，仍保留实际发布时间。

## JSON 备份导入

入口位于【评测与测试】菜单。选择非空且不超过 10MB 的 `.json` 文件；支持系统导出的 1.0 版本对象（版本、数量和 data 数组），也兼容纯记录数组。一次最多导入 1000 条记录。系统逐条检查必填字段、联系方式、日期、ID 唯一性、状态、时间戳、文本长度和图片地址，并仅保存白名单字段。

校验全部通过后才弹出替换确认。确认后一次性替换当前浏览器数据；空备份也会提示记录数并要求确认。取消、读取失败、任意记录不合法或本地存储保存失败，均不写入备份。图片只接受项目 `assets/` 目录中的静态资源、无凭据的 HTTP/HTTPS 地址，或不超过 2MB 的 PNG/JPEG/WEBP Base64。导入验证不代表远程图片地址可访问，也不包含账号或服务器同步。
